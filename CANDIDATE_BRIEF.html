Full-Stack Engineer · Take-Home

Make the agent solid, then make it better.

You're inheriting a small browser app: an agent that answers marketing questions over a fixed dataset and streams its reasoning as it works. It runs — but it's rough around the edges. We'd like to see how you bring something like this up to production quality and extend it.

~2–3 hours Runs in the browser No API key needed AI tools encouraged
This mirrors the actual work: connecting an interface to data and an LLM, making an agent loop behave, and sweating the UX of how reasoning is shown. There are no trick questions — just a real (small) codebase with real rough edges.

Setup — nothing to request, nothing to provision

Requirements: Node 18+. From the project folder:

npm install
npm run dev        # open the printed localhost URL

The app starts in Mock model mode — a scripted, deterministic "model" so the whole thing runs with no API key. Everything in this exercise can be done in mock mode.

Optional (a nice-to-have, not required): copy .env.example → .env.local, drop in a free key from Groq, OpenRouter, or Cerebras, and flip the header toggle to "Real model." Any OpenAI-compatible, tool-calling model works.

Part A — Fix three known issues

A1 · Streaming

The answer doesn't stream

The thinking trace updates live, but the assistant's written answer snaps in all at once when the turn finishes. Make the answer stream in token-by-token as it arrives.

A2 · Agent loop

Comparison questions hang

Single questions work ("what was our blended ROAS in June?"), but anything needing more than one tool call — e.g. "compare Meta and Google for last month" — spins and never lands a clean answer. Make the agent handle a turn where the model requests more than one tool.

A3 · Correctness

The numbers are wrong

At least one metric the agent reports is incorrect. Find the bug(s), fix them, and briefly note how you verified the corrected numbers. Trust nothing; check the math.

Part B — Add one feature

Pick the version you think adds the most value, and keep it tasteful:

When an answer is a comparison or a time series, render a small inline chart in the response — and surface which tool calls / rows the answer is based on (source attribution). Use your judgment on when a visual actually helps versus when it just adds clutter.

Use any libraries or component kits you like — shadcn, Base UI, Recharts, Tremor, whatever you reach for.

Part C — Write it up (short)

1
One-page design note. What each fix was, how you verified the data fix, the biggest risk if this shipped to production, and what you'd do with two more days.
2
~5-minute Loom. Walk through the app and one tradeoff you made.

Ground rules

  • Don't rewrite from scratch. Work in the codebase as given.
  • Keep it runnable — npm install && npm run dev, and mock mode must keep working with no key.
  • Time-box to ~2–3 hours. If you run out of time, say what you'd do next — that counts.
  • AI coding tools are expected. We care about the result and how well you understand it, which the walkthrough will show.

How we'll evaluate

Correctness of the fixes, how cleanly you handle the agent loop, streaming and UX quality, code quality, product judgment (edge cases, when to visualize, statistical significance), and how clearly you communicate. The walkthrough matters as much as the code.

Submitting

  • A link to your repo (GitHub/GitLab) or a StackBlitz/CodeSandbox fork.
  • Your one-page writeup (link or file).
  • Your Loom link.

A live deployed URL (Vercel/Netlify/StackBlitz) is a plus, not a requirement.

About the data: it's a fixed 90-day snapshot where "today" is 2026-07-01, so "last month" means June 2026. Channel names in the raw data are intentionally inconsistent (Meta / meta / Facebook) and a couple of campaigns have gaps (a paused week, a mid-flight launch). That messiness is on purpose.
